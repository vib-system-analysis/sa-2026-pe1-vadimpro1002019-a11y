# Контроль качества разговоров

Учебный проект по курсу «Системы искусственного интеллекта» (2026, 1 курс, направление «Прикладная экономика»). Тема получила оценку **17/20** по фильтру курса.

## О проекте

Супервизор колл-центра успевает прослушать лишь небольшую случайную выборку звонков. Система должна проверять расшифровки разговоров по чек-листу компании: например, поздоровался ли оператор, уточнил ли проблему, предложил ли решение и не пообещал ли невозможного.

Каждый вывод должен сопровождаться цитатой из разговора, чтобы оператор и супервизор могли проверить оценку и обсудить спорные случаи. Критические нарушения, например обещание неподтверждённых сроков или разглашение чужих данных, нужно выявлять отдельно и не пропускать.

**Цель:** перейти от выборочного контроля к систематической проверке и давать оператору понятный разбор с подтверждающими цитатами.

## Что предстоит исследовать

- Какие пункты чек-листа проверяются буквально, а какие требуют учёта контекста.
- Что считать критическим нарушением и какие действия должны следовать за его обнаружением.
- Какие данные из разговора нельзя сохранять и как обеспечить их защиту.
- Как оператор может оспорить оценку и кто принимает итоговое решение.

## Процесс и критерии успеха

- **Пользователь процесса:** супервизор колл-центра, который оценивает работу смены по записям разговоров.
- **Результат:** оценка качества и разбор для оператора; на их основе могут приниматься кадровые решения.
- **Успех:** супервизор согласен с оценкой, критические нарушения не пропущены, а оператор понимает причины снижения оценки.
- **Границы автоматизации:** чек-лист сочетает формальные критерии и пункты, требующие суждения; одного вызова языковой модели недостаточно, чтобы надёжно решить задачу.

## Данные и безопасность

Реальные записи содержат персональные данные и недоступны для проекта. Для разработки будут использоваться только синтетические разговоры: команда разыграет и запишет сценарии, составленные по чек-листу реальной компании. Открытые наборы речи можно использовать для исследования качества распознавания.

Отдельные сценарии проверки безопасности должны учитывать:

- попытки повлиять на систему оценки репликами внутри разговора;
- персональные данные в расшифровках, которые нельзя сохранять.
